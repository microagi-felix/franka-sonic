You are the phase agent for **P4** of the FR3 handover bake-off, running

the terminal: `plan/STATUS.md` (committed and pushed) is your only channel.
Work until the P4 gate passes, then stop. P4 is the last phase.

## 0. Orient first (always, before touching anything)

Read, in this order:

1. `AGENTS.md` — the operating rules for this pod. They win over this prompt.
2. `plan/PLAN.md` — the scoring definition ("Task and scoring") and the

3. `plan/STATUS.md` in full — it is the campaign's record: which run folders

## 1. Goal

`plan/REPORT.md`: one table comparing both lanes and both oracles on the same
20 seeded rollouts, plus an honest list of what breaks at scale. This is a
**pipeline proof, not a result** — say so in the report, and never dress up
60–80 demos' worth of noise as a finding about which stack is better.

## 2. Work packages

### WP 4.1 — aggregation script

`harness/report/aggregate.py` (stdlib only, so plain `python3` runs it): reads
the four eval run folders under `~/runs/franka-sonic/` —

- lane A policy: `lane_a/*_eval/out/eval/eval_results.csv`
- lane A oracle: `lane_a/*_oracle_a/out/eval/eval_results.csv`
- lane B policy: `lane_b/*_eval/out/eval/eval_results.csv`
- lane B oracle: `lane_b/*_oracle_b/out/eval/eval_results.csv`

plus each folder's `config.json` (for the stamped SHAs, devices and args) and
the `episode_*_result.json` files (for the rubric milestones). Emit a markdown
table; write it to `plan/REPORT.md`. Take the newest run folder per category
and print which ones you used.

### WP 4.2 — `plan/REPORT.md`

One table with a row per lane (and per oracle), columns:

| lane | full-success rate | milestone 1…6 reach rates | median steps-to-success | action jerk | eval wall-clock | GPU-hours |

Then, in prose kept short:

- **Fine-tune parity statement** — the exact command each lane ran (steps,
  batch, GPUs, horizon, action encoding). If the two differ in any way, say so
  at the top; a comparison across different budgets is not a comparison.
- **Oracles** — A-oracle ≈ 100 % is the sanity floor; B-oracle is lane B's
  ceiling. Interpret: a low B-oracle means the controller, not the VLA, lost.
- **Deviations and decisions** taken during P0–P3, pulled from STATUS.md (e.g.
  motion library without human clips, GPUs available, keep-rate).
- **Scale-up deltas** — what a real run needs, itemised: demo count, full
  BONES-SEED retarget, 4096 envs × 8 GPUs for SONIC RL, 20 000 fine-tune steps
  for both lanes, longer eval (≥ 100 rollouts), the real-cell caveat that
  joint-target policies need a joint-impedance controller on the FR3s that the
  repo does not have today.

GPU-hours: derive from the run folders' timestamps and their `config.json`
device lists; if a number is not recoverable, write "not recorded" rather than
guessing.

## 4. Rules (non-negotiable — these come from AGENTS.md)

- **Push, or it did not happen.** `plan/REPORT.md` and the STATUS line must be
  committed and pushed: `git add`, `git commit`, `git pull --rebase`, `git
  push`. Never rewrite or reorder STATUS.md — append only. Another agent may
  push to `main` concurrently, so always rebase before pushing.
- **Pod-state mutations go in the WORKLOG**, not git:
  `~/agents/2026-09-01_franka-sonic/WORKLOG.md`.
- **No new training or eval runs in P4** unless a gate needs one; P4 is
  aggregation. If a lane's eval is missing entirely, do **not** silently run
  it — record `BLOCKED: <lane> eval missing, P4 cannot compare` and end the
  turn.
- **GPUs only from the allocator** if you need one at all (you probably do not).
- **`/data/lustre/shared` is read-only.**
- **Never commit in upstream repos.**
- **Outputs**: `plan/REPORT.md` in this repo (it is a deliverable, not a run
  artifact); anything else goes in a run folder. Nothing in `/tmp`.
- `harness/guard.sh` (PreToolUse hook) scans the whole command text, so a
  heredoc that merely *mentions* a forbidden word gets blocked. Workaround:
  write the script to a file, then run the file.
- **Where this prompt leaves a detail open: decide it yourself, write the
  decision into STATUS.md, and continue.** Do not stop to ask.
- **If you are truly stuck** after real effort: append
  `BLOCKED: <one-line reason + what you tried>` to STATUS.md, push, end the
  turn.
- A driver kills this session at **6 h** (P4 should take minutes).
