## Round 2 in one paragraph (read this first)

### WP 7.0 — parameterise the demo stage (harness change, do it first)

4, 4`. Add CLI flags with **exactly these names and defaults so every round-1

### WP 7.1 — widen the training distribution (the point of the phase)
Read how the generated episodes get their cube pose (the MimicGen/Isaac Lab
Mimic path in `franka-bimanual-isaac-sim`, and whatever `stage_demos` passes
it) and how the **evaluation** binding draws its spawns (`seed 0 + episode
index`, ±6 cm / ±0.5 rad — confirm this in the code, do not trust this line).

Then widen the *generation* distribution so it covers the evaluation range with
margin — target **±9 cm / ±0.75 rad** — and, if the knobs exist without
touching the evaluation config, also vary the initial arm pose and the handover
placement point. **The evaluation env, binding, seeds, rate, replan interval
and horizon must not change**: round-2 numbers have to stay comparable with
round 1's, and both lanes must see the identical evaluation. If widening is
only possible by editing something the evaluation also reads, stop and write
the finding into STATUS instead of changing it.

Write the measured spawn distribution of the finished dataset to
`out/coverage.json` in the demos run: min/max/mean/std of cube x, y and yaw
over all episodes, plus the evaluation range and a boolean `covers_eval`.

### WP 7.2 — more sources, then generate
Source demos bound MimicGen's diversity, so raise them: `--n-sources 30`
(~25 min). Then generate with `--n-generated 1000 --n-procs 16` (2 procs per
GPU across 8 devices; claim the devices through the allocator). Watch the first
5 minutes: if a proc dies for GPU memory, halve `--n-procs` and record it.
MimicGen keeps only successful episodes, so `--n-generated` is a target, not a
guarantee — record the keep rate the log prints (`PARALLEL_GEN_DONE … aggregate
k/n = x % success`).

**Time budget: 3 h for generation.** If 1000 kept episodes are not in hand by
then, keep what you have (the gate floor is 600), write the number and the keep
rate into STATUS, and move on. Do not spend the phase here.

### WP 7.3 — export and dataset
Export with `--n-shards 8` (~2 h for 1000 episodes), then
`python3 harness/bakeoff.py run shared dataset --demos <the demos run>` for
`out/gr00t_v2`. Expect ~1.9 GB and ~670 k frames at 1000 episodes; check `df`
before starting (HARD RULE 3).

### WP 7.4 — validate before you hand it on
1. Replay **5 randomly chosen** generated episodes on the JointPos env — all 5
   must reach `handover_success=True`. If any fails, investigate before the
   gate; a silently broken episode set poisons both lanes.
2. `meta/info.json`: episode count, frame count, fps 50, three cameras.
3. `out/coverage.json` from WP 7.1, and state in STATUS whether the training
   distribution covers the evaluation range.
4. One STATUS line with: sources, generated, kept, keep rate, exported,
   dataset episodes/frames/size, coverage verdict, wall-clock per sub-step.
